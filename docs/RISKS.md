# Known Risks & Mitigations

| # | Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|---|
| 1 | Parsers break when a source changes markup/format | High | Ingestion silently stops | Prefer API/RSS sources (structured, stable); `last_run_status = empty` → Sentry alert; per-source isolation so one broken source doesn't stop the rest |
| 2 | Source rate limits / bans | Medium | Loss of a source | Gentle cadence (once per 4h), caching, exponential backoff, honest User-Agent; respect `Retry-After` |
| 3 | Free hosting puts containers to sleep | High | Missed ingestion runs, slow cold starts | **Hit in practice**: GitHub Actions ran the `*/10` keep-alive only every 4–5 h (Oct 2026). The 10-minute tick now comes from Supabase `pg_cron` (ADR-023) and doubles as keep-alive; GitHub workflows stay as a fallback. If pg_cron is ever unavailable, any free HTTP cron (cron-job.org) can call the same hook. `DB (prod)` → `schedule:status` shows the last runs and HTTP answers |
| 4 | Free LLM tiers exhausted (real limit is tokens/day, not requests/day) | Medium (phase 4) | Scoring/summarization stalls | Failover across providers (Groq / OpenRouter / Gemini — ADR-005); batch scoring; summarize context to cut tokens; degrade gracefully to rules-based matching. Groq's free tier also caps tokens *per minute* (8000, output budget included); after a night of empty pushes (2026-10-16) vacancy scoring left the LLM altogether: everyone, the owner included, is scored by the formula, and the background resume pass is gone (ADR-029). The LLM now reads resumes and serves owner-only on-demand features |
| 5 | Scope creep | High | v1.0 never ships | Hard rule: phase N+1 only after current phase is deployed; "out of scope" list in PRODUCT.md |
| 6 | Free-tier limits change or products shut down | Low | Migration required | All infra choices are commodity (Postgres, Redis, SMTP-like email API) — swappable; no vendor-specific features in core logic |
| 8 | Background schedulers burn the Upstash free-tier command budget (500k/mo) | — | — | **Closed by ADR-031 (v2.6.3).** Hit twice: first by the BullMQ planner tick (v1.10.1 moved it to an in-process timer), then on 2026-10-22 by the ingestion queue itself, 90% of the month used by the 22nd at ~600 jobs a day with the 10-minute tick. The queue now runs in process and Redis is no longer used at all |
| 9 | A 10-minute tick multiplies per-cycle costs (ADR-023) | Medium | Supabase egress, LLM quotas or Upstash commands run out | Only due sources are enqueued (idle tick = no Redis commands); dedup reads only companies with fresh vacancies; the background LLM résumé pass is gone (ADR-029). Watch Supabase egress and the Upstash dashboard after the switch |
| 10 | Strangers' resumes reach a free LLM tier that trains on submitted data (phase 5) | Medium | Personal data leak, trust | Non-owner resume analysis uses only providers that do not train on free-tier data (ADR-025 §4); `/privacy` names the provider; `/delete` removes everything |
| 11 | Formula scoring is worse than the LLM verdict (phase 5) | Medium | Users (and since ADR-029 the owner) see noise and leave | Precision ≥ 70% of the formula's top 20 rated ≥80 by the LLM on the author's `resume_matches` (ADR-026; 85% on 2026-10-15); precision does not measure recall; synonym dictionary; `formula:check` in `DB (prod)`. The card no longer has 👍/👎 (v1.28.0), so feedback weights barely move; per-user tuning is now `/settings` filters and the minimum fit |
| 12 | Bot API rate (≈30 msg/s overall, 1/s per chat) with many users after one ingestion run (phase 5) | Medium | Lost or late cards | One send limiter, `429 retry_after`, `403 blocked` turns the digest off (ADR-024 §9). In place since v1.28.0. The run is sequential, so one per second per chat means a user with 60 new cards holds the tick for a minute; parallel sends across chats are the fix if many users wait |
| 13 | A source's owner objects to its vacancies reaching other people (phase 5.4) | Low | A source must be dropped for non-owners, or entirely | Terms re-read per source (DATA_SOURCES.md, "Who receives which source"); every card links to the posting and names the source; `sources.config.ownerOnly: true` takes a source away from non-owners with a seed change and `DB (prod)` → `migrate` |
| 7 | Author burnout / life happens | Medium | Project stalls | Small deployable phases; each phase leaves the project in a usable, resume-worthy state |
| 14 | The quality audit's free LLM judge is wrong or its quota runs out (ADR-035) | Medium | A wrong title word stops good vacancies for everyone, or the morning report is empty | The judge only labels; code adds a word only after the title, technology, regression-set and same-day collateral checks, and the PR is merged only after build, lint, typecheck and tests pass in the job (`AUDIT_AUTO_MERGE=false` turns merging off); a spent provider falls over to the next one, an unjudged day still reports the funnel's numbers |
| 15 | The scheduled fixer ships a wrong fix, or a public issue leaks a user's words (ADR-037) | Medium | A regression in prod, or personal data in a public repository | Fixes go through the same CI and tests as any PR and are reverted like any other; only items the owner marked become issues; issues carry no user id or username and feedback is redacted (emails, handles, `t.me` links, phones) |

Review this table at the end of each phase; add new risks as they surface.
