# JobRadar — агрегатор вакансий + CRM откликов

> Рабочее название: **JobRadar** (альтернативы: JobPilot, HuntBoard, Vacanser — заменить при желании).

## 1. Описание проекта

Персональный сервис для поиска работы, объединяющий две части:

1. **Агрегатор** — фоновые воркеры регулярно собирают вакансии из дружелюбных источников (API, RSS, Telegram), фильтруют по профилю пользователя, дедуплицируют и присылают дайджест.
2. **CRM откликов** — канбан для ведения воронки: сохранённые вакансии → отклик → скрининг → техинтервью → оффер. Заметки по компаниям, напоминания, статистика конверсии.

**Автор и цель:** frontend-разработчик (React, 8 лет), проект — путь к фулстек-опыту. Вторичная цель — реальный инструмент для собственного поиска работы (remote/on-site, фултайм/парт-тайм/фриланс, СНГ и зарубеж). Теоретическая монетизация — подписка для других соискателей (5–10 $/мес), но приоритет — обучение и личное использование.

## 2. Ключевые решения и ограничения

- **Бюджет: $0.** Только бесплатные тиры. Единственная допустимая трата — домен (~10 $/год), опционально.
- **LinkedIn вычеркнут** из автоматического скрейпинга (антибот, нет API, вечная война). Компенсация — browser extension для ручного сохранения вакансии в один клик (фаза 4).
- **Источники v1:** hh.ru (официальный бесплатный API), RemoteOK / WeWorkRemotely (RSS/JSON), HN Who's Hiring, Telegram-каналы с вакансиями (Telegram API). Djinni — позже, парсингом.
- **Скрейпинг щадящий:** раз в несколько часов, кэширование, без прокси. Прокси — только «проблема успеха», не сейчас.
- **Дедупликация:** эвристика (нормализованная компания + fuzzy-match тайтла), позже — LLM-матчинг.
- **LLM-скоринг вакансий** («насколько подходит под мой профиль») — через бесплатные тиры (Groq / OpenRouter / Gemini) с failover между провайдерами. Учитывать: реальный лимит — токены/день, а не запросы/день.
- **Бэкенд отдельно от фронта** — сознательно, чтобы получить настоящий бэкенд-опыт (миграции, очереди, докер, деплой), а не «API-роуты в Next.js».

## 3. Стек

| Слой | Выбор | Примечание |
|---|---|---|
| Frontend | React + Next.js (или Vite SPA) | сильная сторона автора |
| Backend | NestJS (или Fastify) + TypeScript | отдельный сервис |
| БД | PostgreSQL (Neon или Supabase free) | + полнотекстовый поиск Postgres FTS |
| ORM | Prisma или Drizzle | + миграции |
| Очереди/кэш | Redis (Upstash free) + BullMQ | фоновые джобы скрейпинга |
| Cron | GitHub Actions schedule | бесплатно, обходит «засыпание» контейнеров |
| Email | Resend (3000 писем/мес free) | дайджесты, напоминания |
| Telegram | Bot API | второй канал доставки дайджеста |
| Хостинг | Vercel (front) + Railway/Fly.io (back) | бесплатные тиры |
| Мониторинг | Sentry free | ошибки фронта и бэка |
| CI/CD | GitHub Actions | линт, тесты, деплой |

## 4. Скоуп версии 1.0 (минимум, доведённый до продакшена)

1. Авторизация (email + пароль или OAuth GitHub/Google).
2. Профиль поиска: ключевые слова, стек, формат (remote/on-site), тип занятости, вилка.
3. Ингест из **двух** источников: hh API + одна remote-доска (RSS).
4. Лента вакансий с фильтрами + полнотекстовый поиск.
5. Канбан откликов (drag-and-drop, 5 стадий, заметки).
6. Email-дайджест новых подходящих вакансий раз в день.
7. Деплой: домен/поддомен, HTTPS, CI/CD, Sentry.

Всё остальное — за пределами v1.0. Правило: не начинать фазу N+1, пока v-текущая не задеплоена.

## 6. Известные риски

| Риск | Митигция |
|---|---|
| Парсеры ломаются при изменении вёрстки | приоритет API/RSS-источникам; алерты в Sentry при пустом ингесте |
| Rate-limit источников | щадящая частота, кэш, экспоненциальный backoff |
| Бесплатный хостинг усыпляет контейнеры | cron снаружи (GitHub Actions), health-пинг |
| Лимиты бесплатных LLM (токены/день) | failover между провайдерами, суммаризация контекста, скоринг батчами |
| Скоуп-крип | правило «фаза N+1 только после деплоя текущей» |
